# 过程文件模板 / Artifact Templates

四个核心过程文件的最小模板。模板是最小集：字段不可删除，允许按需增加。文件头字段契约见 `references/agent-artifacts-rules.md` 第 1 节。

## 目录

1. PLAN（计划）
2. HANDOFF（任务交接单）
3. ADR（架构决策记录）
4. STATUS（状态报告）

## 1. PLAN

```markdown
# PLAN: <计划名>

- 目标：<一句话，说明本计划达成什么；含量化指标>
- 状态：draft
- 负责人：<姓名或 Agent 标识>
- 最后更新：YYYY-MM-DD

## 范围

<本计划覆盖什么、不覆盖什么。边界用「包含 / 不包含」两列表述。>

## 任务分解

1. <任务> — 负责人 — 完成条件：<量化验收>
2. ...

## 风险与假设

- 假设：<假设>；若不成立：<后果>
- 风险：<风险>；缓解：<措施>

## 关联

- 取代：<旧文件，若有>
- 相关 ADR：<编号，若有>
```

## 2. HANDOFF

```markdown
# HANDOFF: <任务名>

- 目标：<交接目的>
- 状态：active
- 负责人：<接收方>
- 最后更新：YYYY-MM-DD
- 上游：<交付方>

## 已完成

- <可独立验证的事项，附证据：测试数、文件路径、输出>
- （无）

## 待办

- <事项> — 负责人 — 完成条件：<量化验收>
- （无）

## 风险

- <坑 / 假设 / 假设不成立的后果>
- （无）
```

## 3. ADR

```markdown
# ADR-NNN: <决策标题>

- 状态：draft
- 负责人：<决策责任人>
- 最后更新：YYYY-MM-DD

## 背景

<问题、约束、假设。引用被取代的旧 ADR。>

## 决策

<一句话，陈述句，主语显式。>

## 理由

<为什么是这个方案。>

## 备选方案

1. <方案> — 被否原因：<原因>
2. <方案> — 被否原因：<原因>
```

## 4. STATUS

```markdown
# STATUS: <周期>（YYYY-MM-DD）

- 状态：active
- 负责人：<报告人>
- 最后更新：YYYY-MM-DD

## 进展

- <自上次报告以来完成的可验证事项>

## 阻塞

- <事项> — 需要的帮助：<具体请求>
- （无）

## 下一步

- <事项> — 完成条件：<量化验收>

## 指标

- <量化项>
- （无）
```

## 使用约定

- 三段式（已完成 / 待办 / 风险）字段名保持原词。linter 的 `--kind` 检查按字段名匹配，改名即失效。
- 「（无）」是显式空值，区别于「忘了写」。禁止留空白段落。
- 模板中的 `<...>` 占位符在定稿时必须全部替换。
