# Multi-Agent 过程文件规范 / Agent Artifact Rules

本文件定义规范对象 B（Vibe Coding 中 Multi-Agent 协作产生的过程文件）的全部规则条目。模板见 `references/templates.md`。

适用文本：PLAN、任务交接单（handoff）、架构决策记录（ADR）、记忆文件、状态报告、评审记录、CHANGELOG 条目。

## 1. 文件头契约

每份过程文件的开头必须是一个元数据块。缺头即不合格（linter 在 `--kind` 模式下硬性检查）。

| 字段 | 必填 | 说明 |
|---|---|---|
| 目标 / Goal | plan 必填 | 一句话说明本文件存在的目的 |
| 状态 / Status | 全部必填 | 生命周期状态，取值见第 2 节 |
| 负责人 / Owner | 全部必填 | 当前责任人；无人认领是流程 bug |
| 最后更新 / Updated | 全部必填 | ISO 日期（YYYY-MM-DD） |

linter 规则：`kind-contract`（H-B1，硬性）。各 kind 的必需字段：`plan = 目标, 状态, 最后更新`；`handoff = 已完成, 待办, 风险`；`adr = 状态, 决策, 备选`；`status = 进展, 阻塞, 下一步`。

## 2. 状态机与生命周期

过程文件的状态取值必须来自同一枚举，不允许自由发挥：

- **草稿 draft**：编写中，可被大幅修改。
- **生效 active**：当前事实来源（source of truth），修改必须留痕。
- **已决策 decided**（仅 ADR）：决策已定，内容冻结，只允许补充后果记录。
- **已废弃 superseded**：被新文件取代；文件头必须注明取代者。
- **已完成 done**：目标达成，只读归档。

- **H-B2** 状态字段只允许以上取值（ADR 用 decided）。「进行中（差不多快好了）」不是状态。
- **H-B3** 状态变更必须更新「最后更新」日期。

## 3. 交接三段式（handoff）

Multi-Agent 协作的最高风险点是任务交接。下游 Agent 无法向上游提问，交接单必须包含且仅包含三段：

- **已完成 Done**：本次完成的事项，逐项列出，可验证。
- **待办 Todo**：未完成事项，每项附负责人（或明确「待指派」）与预期完成条件。
- **风险 Risk**：已知的坑、假设、以及「如果假设不成立会发生什么」。

- **H-B4** 三段缺一即不合格。段落允许为空，但必须显式写「无」——空段落与「忘了写」无法区分，「无」可以。
- **H-B5** 已完成事项必须可被独立验证。「重构了模块」不合格。合格示例：「将 parser.py 的 tokenize 函数拆分为两个函数，42 个测试全部通过」。
- **H-B6** 待办事项必须含完成条件，参照规范对象 A 的量化验收（H-A5）。

## 4. 决策记录规范（ADR）

格式继承 Michael Nygard 的 ADR 结构。按 GB/T 8567 的文档编制要求补充元数据。

- **H-B7** 每份 ADR 记录一个决策。多个决策拆为多份文件，文件名编号（ADR-001、ADR-002）。
- **H-B8** ADR 必须包含四要素：背景、决策、理由、备选方案。背景含约束与假设。决策用一句话陈述。备选方案至少一个，附被否原因。
- **H-B9** 决策必须可回指：被该决策取代的旧 ADR 标记 superseded，并在新 ADR 的背景中引用。
- **A-B1**（建议）ADR 的备选方案不少于一个。没有备选方案的决策记录，通常是先决策后补文档。

## 5. 记忆文件规范

长期记忆文件（跨会话持久化的知识）遵循「事实与出处分离」：

- **H-B10** 每条记忆包含：事实陈述、来源（文件 / 提交 / 对话日期）、置信度（确认 / 推测）。
- **H-B11** 推测性记忆必须标注「推测」，且禁止升级为事实而无新证据。
- **H-B12** 记忆文件同样适用文件头契约；失效记忆不删除，标记「已废弃」并注明取代者（与 ADR 生命周期一致）。

## 6. 状态报告规范

周期性状态报告（人或 Agent 向项目 Owner 汇报）：

- **H-B13** 固定四段：进展、阻塞、下一步、指标。进展列可验证事项。阻塞附需要的帮助。下一步含完成条件。指标无量化项时写「无」。
- **H-B14** 报告不引入新决策。需要决策的事项写入 ADR 或 Issue，报告中只引用。

## 7. 变更记录规范

- **H-B15** CHANGELOG 条目遵循 Keep a Changelog 分类。四类：Added、Changed、Fixed、Removed。每条附日期与关联 ADR 或提交号。
- **H-B16** 版本号遵循 SemVer。过程文件本身的版本在其文件头注明。

## 8. 文件间一致性

- **H-B17** 过程文件之间出现事实冲突时，以生命周期状态最高的文件为准（active > draft > done 归档）。冲突本身必须记录为风险或 Issue。
- **H-B18** 过程文件全文适用规范对象 A 的全部表达规则（`references/human-expression-rules.md`）。过程文件不是表达规则的豁免区——恰恰相反，它是无回溯信道读者的主要场景。
